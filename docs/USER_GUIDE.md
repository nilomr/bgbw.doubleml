# BGBW Trends — User Guide

How to set up, configure, and run the current pipeline implementation.

---

## 1. Data requirements

The pipeline currently reads from four external sources:

| Source | Expected files |
|---|---|
| Harmonized surveys | `bgbw_{year}.parquet` — individual-level BGBW submissions |
| Geospatial embeddings | `aef_bng1km_{year}_uk.parquet` — one row per 1 km BNG cell |
| Survey-weekend weather | HadUK-Grid parquet |
| January weather | HadUK-Grid parquet |

See the project kanban for the current status of these variables and others in progress or under consideration.

Harmonized survey files are produced by the BGBW data pipeline repo
(`bgbw.data.pipeline`). The trends pipeline aggregates them to 1 km BNG
cells at runtime, then joins embeddings and weather. Set the paths in your
config file (see §2).

---

## 2. Configuration

Every run is driven by a YAML config file. Two are provided in [`configs/`](../configs/):

| File | Purpose |
|---|---|
| [`configs/local.yaml`](../configs/local.yaml) | Local development — single species, quick settings |
| [`configs/cluster.yaml`](../configs/cluster.yaml) | Cluster run — all species, full model, more workers |

Copy either file to create a new experiment config. The sections are:

```yaml
paths:                        # data locations — edit per machine
  harmonized_dir: /data/bgbw/harmonized
  aef_dir: /data/bgbw/aef
  weather_path: /data/bgbw/weather/bgbw_weather.parquet
  january_weather_path: /data/bgbw/weather/bgbw_january_weather.parquet

run:
  species: all                # "all" = all 73 species, or a list e.g. [blackbird, robin]
  years: [2017, 2019, 2021, 2023]
  output_dir: output/myrun

model:
  n_pca_components: 15        # PCA dim for embeddings; 0 = no PCA
  n_estimators: 500           # trees in nuisance random forests
  cf_n_estimators: 500        # trees in causal forests
  rf_min_samples_leaf: 10
  cf_min_samples_leaf: 50

compute:
  n_workers: 20               # parallel ensemble/RC workers
  inner_n_jobs: 5             # threads per RF/CF fit (n_workers × inner_n_jobs ≤ total CPUs)

ensemble:
  run: true
  n_ensemble: 100             # ≥25 for usable CIs; 100 for publication quality
  n_rc_sims: 100              # ≥25 for stable bias estimate

log_file: logs/myrun.log      # null to disable file logging
```

A copy of the resolved config is written to `output/<run>/config.yaml` at the
start of every run, so results are always traceable to the exact parameters used.

Key notes:

- `reference_effort` is computed automatically; do not set it manually.
- `SPECIES_COLUMNS` in [`config.py`](../src/bgbw_trends/config.py) lists all 73
  supported species (used when `species: all`).

## 3. Running the pipeline

```bash
# Local development run
uv run python scripts/pipeline/run_prototype.py configs/local.yaml

# Full cluster run
uv run python scripts/pipeline/run_prototype.py configs/cluster.yaml

# Custom experiment — copy and edit a config, then run it
cp configs/local.yaml configs/sensitivity_1000trees.yaml
# edit configs/sensitivity_1000trees.yaml ...
uv run python scripts/pipeline/run_prototype.py configs/sensitivity_1000trees.yaml
```

Fits the two-part DML model for each species, saves predictions and figures,
runs the residual-confounding diagnostic, and optionally fits an ensemble for
uncertainty quantification — all for every species in the config.

**Note on hurdle independence.** The prototype splits training data into two
non-overlapping 50/50 stratified halves via `split_cell_years` — one for the
occurrence stage, one for the count stage — so the chain-rule combination
(`abd_ppy = τ_occ/P(occ) + τ_count`) is based on independent
estimates. For uncertainty quantification use `fit_ensemble_trend`
from [`trends/ensemble.py`](../src/bgbw_trends/trends/ensemble.py), which
repeats this split across multiple ensemble members.

### Map products

```bash
uv run python scripts/pipeline/make_maps.py             # standard maps from saved parquets
uv run python scripts/products/make_hex_map.py          # hexbin aggregated maps
uv run python scripts/products/make_decoupling_map.py   # occurrence / count decoupling
```

These read the prediction parquets saved by `run_prototype.py` and regenerate
figures without re-fitting any models. `make_maps.py` writes standard trend,
SDM, and bivariate maps; the product scripts add `hex_abundance.png` and
`hex_decoupling.png`.

## 4. Outputs

Core pipeline outputs land under `cfg.output_dir`:

```
output/<run>/
├── predictions/species/<species>/prediction.parquet
├── ensemble/species/<species>/ensemble.parquet
├── diagnostics/
│   └── pipeline_model_diagnostics.csv
└── figures/
  ├── maps/<species>/              optional; generated by the map scripts
    └── species/<species>/
        ├── sdm.png                   P(occurrence) and E[abundance] maps
        ├── trend_ppy_panels.png      spatial trend maps (occ, count, abd)
        ├── yearly_trend.png          ATE and ensemble trend over time
        ├── raw_vs_fitted.png         deconfounded trend line
        ├── distribution_summary.png  prediction distributions with CIs
        ├── shap_sdm.png              SDM feature attributions
        └── shap_cate.png             τ(W) feature attributions
```

The prediction parquet has one row per 1 km BNG cell:

| Column | Description |
|---|---|
| `bng_ref` | 1 km British National Grid reference |
| `p_occurrence` | P(detected \| X, reference effort) |
| `e_count_given_occ` | E[count \| detected, X, reference effort] |
| `e_abundance` | relative abundance (`p_occurrence × e_count_given_occ`) |
| `occ_ppy` | occurrence trend (% per year) |
| `count_ppy` | count trend (% per year, given occurrence) |
| `abd_ppy` | combined abundance trend (chain rule) |
| `occ_sigma` | causal forest SD for occurrence CATE (if computed) |
| `count_sigma` | causal forest SD for count CATE (if computed) |

If `ensemble.run: true`, an ensemble parquet is produced for every configured
species, adding `abd_ppy_lower` and `abd_ppy_upper` (10th/90th percentile
across ensemble members).

## 5. Adding a new species

All 73 species in `SPECIES_COLUMNS` are ready to use. Set `species: all` in your
config to run them all, or list specific names:

```yaml
run:
  species: [song_thrush, mistle_thrush]
```

Two things to watch for:

- **Sparse species.** The count stage requires at least 50 detected cell-years.
  Species below this threshold currently raise a `ValueError` in
  `train_predict_species`; the prototype script does not skip them
  automatically. Filter such species out before a batch run, or add a wrapper
  that catches and records failures.
- **Range-restricted species.** The model fits UK-wide. For species genuinely
  absent from large parts of the grid, SDM predictions outside the range will
  be near zero but the fit may be noisier. Restricting the training frame to
  the known range tends to improve count-stage performance.

## 6. Extending the time series

The default config uses every other year (2017, 2019, 2021, 2023) for speed;
set `years: [2017, 2018, 2019, 2020, 2021, 2022, 2023, 2024]` in your config
for the full annual run. To extend the time series:

1. Produce harmonized survey parquets for the new year(s) using the data
  pipeline repo and place them in the directory listed under `paths` in
  your config.
2. Add the new year(s) to `run.years` in your config.
3. For study periods beyond roughly five years, consider switching to per-year
   embeddings — the current multi-year mean is adequate for short spans but
   land-cover change becomes a real confounder over a decade. See
   [Developer Guide §3.1](DEVELOPER_GUIDE.md#31-embeddings-current-approach-and-roadmap).
4. Re-run the residual confounding diagnostic; its noise floor grows with the
   time span.

Year enters the model as a raw calendar value. Centering is implicit —
DML residualization removes the year-level mean predicted from X, so no
manual pre-centering is needed.

## 7. Diagnostics

### Model quality checks

```bash
uv run python scripts/diagnostics/plot_effort_features.py
uv run python scripts/diagnostics/plot_embedding_pca.py
uv run python scripts/diagnostics/plot_embedding_pcs.py
```

The pipeline run also saves `diagnostics/pipeline_model_diagnostics.csv` with
per-species metrics for both the marginal and propensity forests.

### Propensity R²

The most informative single diagnostic is the **propensity R²**: how well year
can be predicted from X. It is printed to the console after each species fit
and saved in the diagnostics CSV.

- High R² (> 0.85) means the features are absorbing strong temporal confounding
  — DML is doing real work.
- R² near zero means either little temporal confounding in this species' data,
  or the feature set is missing the relevant confounders.
- Extremely high R² (> 0.95) may indicate a year-proxy feature has leaked
  into X.

### Residual confounding

The prototype script runs a null-trend simulation automatically for the first
species in `cfg.species` and prints a summary to the console. The simulation
perturbs the treatment while preserving all feature-year correlations, then
checks whether the resulting "zero-trend" data produce near-zero trend
estimates. Large residual bias indicates missing confounders. The underlying
implementation is in
[`trends/residual_confounding.py`](../src/bgbw_trends/trends/residual_confounding.py).
